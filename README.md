# InvJ — арена решений для Jev-подобных моделей

Приложение для проверки того, насколько хорошо **Jev** (TypeSafe, System-1 decision model) и похожие модели
принимают инвестиционные решения. Несколько агентов одновременно «торгуют» на исторических данных:
на закрытии каждой свечи модель решает, что делать, сделка исполняется по открытию следующей свечи,
и потом видно, что на самом деле произошло.

```
┌──────────────────────┐ ┌──────────────────────┐ ┌──────────────────────┐
│ Jev          ● идёт  │ │ Laya (local) ● идёт  │ │ Claude Haiku  ● идёт │
│ ▁▂▃▅▆▇ свечи + L/S/X │ │ ▁▂▃▅▆▇               │ │ ▁▂▃▅▆▇               │
│ +12.3% | B&H +8.1%   │ │ +4.0% | B&H +8.1%    │ │ -2.1% | B&H +8.1%    │
│ прогноз 58% | $0.042 │ │ 51% | $0.003 (≈)     │ │ 49% | $0.31          │
│ ▶ ⏸ ⏭ ■  ⚙  детали  │ │ ...                  │ │ ...                  │
└──────────────────────┘ └──────────────────────┘ └──────────────────────┘
┌──────────────────────┐ ┌──────────────────────┐
│ SMA cross (бейзлайн) │ │   ＋ Добавить агента │
└──────────────────────┘ └──────────────────────┘
```

## Что умеет

- **Сетка окон-агентов**: у каждого своя модель, данные, входные признаки, вопросы, брокер и скорость.
  Старт / пауза / шаг / стоп для каждого окна и для всех сразу.
- **Модели**
  | provider    | что это | как вызывается | стоимость |
  |-------------|---------|----------------|-----------|
  | `jev`       | TypeSafe Jev | OpenRouter `POST /api/v1/systemone`, модель `~typesafe/jev-latest` | `usage.cost` из ответа |
  | `systemone` | любой сервер с протоколом Jev (например, `laya-serve`) | `POST {base_url}/v1/systemone` | время × `cost_per_hour_usd` |
  | `laya`      | [Laya](https://pypi.org/project/laya/) в процессе (Apache-2.0, открытые веса, 421M) | `laya.Router().predict()` | время × `cost_per_hour_usd` |
  | `gliner`    | [GLiNER](https://github.com/urchade/GLiNER) в процессе, как zero-shot классификатор | `predict_entities()` | время × `cost_per_hour_usd` |
  | `llm`       | любая чат-модель на OpenRouter (только API) | `chat/completions` + JSON-схема | `usage.cost` из ответа |
  | `baseline`  | buy&hold, пересечение SMA, random, always_hold | локально | $0 |
- **Одинаковые вопросы для всех.** Jev и Laya — классификаторы, поэтому каждая модель отвечает на одни и те же
  типизированные вопросы с фиксированными вариантами: `action` (open_long / open_short / close / hold),
  `size` (25 / 50 / 100 % капитала), `forecast` (up / down / flat через N свечей). LLM ограничены JSON-схемой
  с этими же вариантами, так что сравнение честное.
- **Данные**: Binance (без ключа) и CSV (загрузка из UI). Новые источники подключаются одним классом.
- **Анонимизация** (галочка в конфиге): скрывает тикер и даты, цены пересчитываются от 100. Прогон одной модели
  с анонимизацией и без неё показывает, сколько её результата — «память» истории.
- **Метрики**: доходность против buy&hold, просадка, Sharpe, сделки и win rate; точность прогноза против доли
  самого частого исхода, Brier score, матрица ошибок, точность направления входов; **затраты**: всего, за решение,
  по типам действий, токены, задержка, PnL на $1 затрат.
- **Мониторинг**: live-обновления по WebSocket, история всех запусков, журнал каждого решения с **сырым запросом
  и ответом модели**, вероятности по вариантам, рассуждение LLM.
- **Арена**: выбранные агенты перезапускаются на одних и тех же свечах (загружаются один раз), лидерборд и
  общий график доходности.
- **Конфиги**: YAML-пресеты в `backend/presets/`, экспорт и импорт всего рабочего пространства, JSON-режим в форме.
- **Остановка на фатальных ошибках**: нет ключа, 401/402/403/404 или N неудачных вызовов подряд — прогон
  останавливается, а не копит сотни одинаковых ошибок.

## Быстрый старт

```bash
cp .env.example .env            # впишите OPENROUTER_API_KEY

# backend
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"         # + ".[laya]", ".[gliner]" или ".[local]" для локальных моделей (torch)
uvicorn app.main:app --reload   # http://localhost:8000

# frontend (в другом терминале)
cd frontend
npm install
npm run dev                     # http://localhost:5173 (проксирует /api и /ws на :8000)
```

Одним контейнером: `docker compose up --build` → http://localhost:8000.
Laya отдельным сервером: `docker compose --profile laya up`, затем агент с `provider: systemone`,
`base_url: http://laya:8001`.

Без сети и ключей работает пресет **Demo (offline)**: SMA-бейзлайн на `data/csv/SAMPLE-SYNTH.csv`.
Это **синтетические** данные (`scripts/make_sample_csv.py`), не реальный рынок.

Тесты: `cd backend && pytest` (30 тестов; сеть и модели заменены моками), `cd frontend && npm run build`.

## Как это устроено

```
backend/app/
  data/        DataProvider: binance, csv            ← новые источники данных
  features/    Featurizer: свечи + индикаторы + позиция → state (текст или JSON), анонимизация
  decision.py  вопросы к модели (схемы) и как ответы превращаются в ордера
  models/      DecisionModel: jev, systemone, laya, gliner, llm, baseline
  engine/      runner (цикл реплея), broker (бумажный брокер), metrics, manager (все окна, арена)
  db.py        SQLite: агенты, запуски, каждый шаг с сырым I/O
  main.py      REST + WebSocket, раздаёт собранный фронтенд
frontend/src/  React + lightweight-charts: сетка агентов, детали, форма, лидерборд, арена
```

Шаг реплея: после закрытия свечи `i` строится state из свечей `0..i` (будущее недоступно), модель отвечает,
ордер исполняется по `open[i+1]` с комиссией и проскальзыванием, капитал считается по `close[i+1]`.
Прогноз оценивается только когда реплей дошёл до свечи `i + horizon`.

### Как расширять

- **Другие входные данные** (новости, стакан, несколько таймфреймов): подкласс `Featurizer`
  в `app/features/`, `@register_featurizer("name")`, в конфиге `features.name: name`.
- **Другая структура ответа / что проверяем**: `decision.schema_name: custom` и свой список `questions`
  (роли `action`, `size`, `forecast`; вопросы без роли просто логируются, удобно для экспериментов).
  Можно также добавить именованную схему в `decision.py`.
- **Новый источник данных**: подкласс `DataProvider` в `app/data/`, `@register_provider("name")`.
- **Новая модель**: подкласс `DecisionModel` в `app/models/`, `@register_model("name")`.
  Всё, что говорит на протоколе Jev `/v1/systemone`, уже работает через `provider: systemone`.

## Что не проверено вживую

Из среды разработки не было доступа к OpenRouter, Binance и HuggingFace, поэтому:
- Эндпоинт Jev (`/api/v1/systemone`, модель `~typesafe/jev-latest`) и формат ответа взяты из документации
  OpenRouter/TypeSafe и из `laya.serve`, который реализует тот же протокол. В тестах — моки.
  Если OpenRouter поменяет путь, задайте `base_url` агента. Есть ещё Decisions API (`/api/alpha/decisions`),
  он пока не подключён.
- Id LLM-моделей в пресетах (`anthropic/claude-haiku-4.5`, `openai/gpt-5-mini`) сверьте с каталогом OpenRouter.
- Laya и GLiNER проверены на подменных модулях с их реальными сигнатурами (`Router.predict`,
  `GLiNER.predict_entities`); реальные веса не загружались. У английского чекпойнта Laya контекст 512 токенов,
  поэтому пресет использует `typed-decisions` (1024) и окно 20 свечей.
- GLiNER не создан для решений: здесь он классифицирует словесное описание состояния по меткам вроде
  «bullish buy signal». Это слабый, но честный бейзлайн.
